# OpenBot v1 implementation plan

Each work package (WP) is owned by exactly one agent. Owned paths are disjoint within a wave. Every agent follows these rules:

- Read `AGENTS.md`, `docs/decisions.md` and `docs/architecture.md` §1–3, plus your package section.
- Write **only** inside your owned paths. Never edit root manifests or run `bun add` / `bun install`. If you need a dependency that is missing, record it in `openIssues`.
- Persist progress early: write files as you go, not at the end.
- Acceptance applies to every WP: `bunx tsc --noEmit -p <pkg>` passes, `bun test <pkg>` passes, and code follows the Effect 4 idioms in `docs/research/effect4-core.md`.
- Port from the `vendor/scratch/*` seeds where noted. Never import from `vendor/`. Add MIT attribution headers when porting t3code code.

## Wave 3: integration, parity and hardening

- **W3.1 integration and e2e.** Full Playwright flows with harness-fake: onboarding, create bot, DM, approval, question, group chat with mentions, bot-to-bot `message_bot`, routine `runNow`, browser computer view (Chromium), remote node pairing via a second daemon process. Fix integration bugs.
- **W3.2 visual parity.** Screenshot every screen in dark and light, compare side by side against `vendor/design-refs/grok-bot/app/*.png`, and fix spacing, color and typography deltas.
- **W3.3 live harness smoke.** Gated runs with real Claude (haiku), Codex (cheapest model) and OpenCode (user's default), one turn each plus one MCP tool call each. Report results; never spend beyond trivial amounts.
- **W3.4 review.** Adversarial code review per package (correctness, Effect resource safety, security), then a fix loop.
- **W3.5 docs.** README (quick start: brain only; adding a remote node), `docs/node-protocol.md`, harness setup, and a security note.
